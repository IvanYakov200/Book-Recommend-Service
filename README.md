# Прототип книжного рекомендательного сервиса (Goodbooks-10k)

Учебный проект: реализация, анализ и сравнение подходов к рекомендациям книг: от популярного
до гибрида коллаборативной и контентной моделей. Весь код, графики и пояснения лежат в
[`notebook.ipynb`](notebook.ipynb).

> **Примечание.** Файл `to_read.csv` (отметки «хочу прочитать») намеренно не использовался:
> по заданию работа строится на `ratings.csv`, `books.csv`, `tags.csv` и `book_tags.csv`.
> Возможное использование `to_read.csv` описано в разделе «Идеи для улучшения».

## Структура

```
.

├── requirements.txt    # зависимости

    ├── book_tags.csv   # теги книг (goodreads_book_id, tag_id, count)
```

## Запуск

```bash
pip install -r requirements.txt

```

Полный прогон занимает ~5–7 минут (дольше всего идёт подбор параметров SVD и PureSVD).
Все случайные операции зафиксированы через `random_state`/`seed`.

## Логика решения

### Этап 1. EDA
- **Ловушка с ID:** `ratings.book_id` = `books.id`, а `book_tags.goodreads_book_id` = `books.book_id`.
  Таблицы соединяются через маппинг.
- Удалены 2 278 дубликатов пар (user, book).
- **Найденные проблемы данных:**
  - смещение оценок вверх: 66% оценок равны 4–5, средняя 3.86;
  - холодный старт: у трети пользователей меньше 5 оценок;
  - смещение популярности: топ-10% книг собирают 57% всех оценок на Goodreads;
  - разреженность: заполнено 0.18% матрицы user × book;
  - особенность выборки: в `ratings.csv` около 100 оценок на книгу (выборка обрезана авторами
    датасета), а самые частые теги служебные (`to-read`, `owned`…).

### Этап 2. Базовые и контентные модели
- **Popularity:** средний рейтинг с порогом минимального числа оценок, а также байесовский
  (взвешенный, формула IMDb) рейтинг.
- **Content:** профиль книги = `original_title` + топ-30 тегов без служебных тегов. Затем
  TF-IDF (`max_df=0.5`, теги склеены в один токен) и косинусная близость.
  `get_similar_books(book_id, N)` считает схожесть «на лету», без матрицы 10k × 10k.

### Этап 3. Item-Based CF
- Разреженная матрица оценок (`scipy.sparse`): 12 МБ вместо 4.3 ГБ.
- Схожесть: **adjusted cosine** (центрирование по пользователю, аналог Пирсона) + **shrinkage**
  `n/(n+λ)`, штраф за маленькое пересечение читателей.
- Предсказание: взвешенное среднее оценок пользователя по K ближайшим книгам.
- **Находка:** ранжирование по предсказанной оценке даёт Precision@10 ≈ 0.001. Поэтому
  Top-N ранжируется по «силе доказательств» Σ sim·(r − r̄ᵤ).
- Разобраны вычислительная сложность (O(I²·U) наивно) и способы масштабирования.

### Этап 4. Матричные разложения (SVD)
- Разбиение train/test: 80/20 **внутри каждого пользователя** (в данных нет времени оценок).
- Funk SVD из `surprise`, гиперпараметры подобраны **кросс-валидацией на train**.
- `get_recommendations(user_id, N)`: векторизованный расчёт μ + bᵤ + bᵢ + qᵢᵀpᵤ для всех книг,
  для новых пользователей fallback на популярное.

### Этап 5. Оценка и сравнение
- Precision@K, Recall@K, nDCG@K (K = 5, 10). Релевантные книги: оценка ≥ 4 в тесте.
- Одни и те же 3 000 пользователей для всех моделей; дополнительно Coverage и Personalization,
  бутстрэп-интервалы и разбивка по активности пользователей.
- Добавлен **PureSVD**: усечённое SVD неявной матрицы «понравилось / нет», 500 факторов.

### Этап 6. Гибрид
- Взвешенный гибрид PureSVD + Content, вес CF зависит от активности: `w = n / (n + β)`.
- β подобран на **отдельных 2 000 пользователях**, не пересекающихся с оценочными.
- Единая функция `recommend()` с холодным стартом: гибрид / онбординг по любимым книгам /
  популярное. Для новой книги контентная модель находит пользователей, которым её показать.

## Результаты

| Модель | Precision@10 | Recall@10 | nDCG@10 | Coverage | RMSE |
|---|---|---|---|---|---|
| Random | 0.0003 | 0.002 | 0.001 | 95% | — |
| Popularity | 0.0007 | 0.002 | 0.002 | 0.2% | — |
| SVD (surprise) | 0.0005 | 0.001 | 0.001 | 0.2% | **0.832** |
| Content (TF-IDF) | 0.045 | 0.168 | 0.129 | 69% | — |
| Item-CF | 0.052 | 0.149 | 0.137 | 80% | 0.912* |
| PureSVD (implicit) | 0.068 | 0.193 | 0.163 | 56% | — |
| **Hybrid (PureSVD + Content)** | **0.073** | **0.222** | **0.182** | 72% | — |

\* RMSE Item-CF посчитан на подвыборке из 3 000 пользователей. Для сравнения: константа даёт RMSE 0.98,
одни смещения μ + bᵤ + bᵢ дают 0.843.

nDCG@10 по сегментам активности:

| Модель | ≤ 5 оценок | 6–20 | > 20 |
|---|---|---|---|
| Content | 0.124 | 0.131 | 0.132 |
| Item-CF | 0.061 | 0.142 | 0.204 |
| PureSVD | 0.096 | 0.149 | 0.248 |
| **Hybrid** | **0.138** | **0.165** | **0.251** |

## Главные выводы

1. **Лучшая модель — гибрид PureSVD + Content.** Он выигрывает во всех сегментах, сильнее всего
   у холодных пользователей. Парный бутстрэп подтверждает значимость улучшения над PureSVD.
2. **Низкий RMSE не означает хорошие рекомендации.** SVD с лучшим RMSE ранжирует на уровне
   случайного угадывания: его предсказание определяется смещением книги bᵢ, и всем выдаётся один
   и тот же список. Модель надо обучать под задачу, на которой её оценивают; для Top-N это неявный
   сигнал «что человек выбирает читать».
3. **Нет одной лучшей модели для всех пользователей.** Content лучше для новичков, коллаборативные
   модели лучше для активных пользователей. Отсюда гибрид с весом, зависящим от активности.
4. Popularity на этих данных не работает из-за обрезанной выборки (около 100 оценок на книгу); в
   реальном сервисе с длинным хвостом он был бы сильнее.

## Ограничения
- Случайное (а не временное) разбиение: в датасете нет времени оценок.
- Обрезанная выборка оценок ослабляет эффекты популярности.
- Непрочитанная книга считается нерелевантной, хотя могла бы понравиться.

## Идеи для улучшения
- Модели для неявного фидбека: implicit ALS, BPR, LightFM, EASE; сигнал из `to_read.csv`.
- Текстовые эмбеддинги (Word2Vec, BERT/sentence-transformers) вместо TF-IDF.
- Фичи пользователей и книг (автор, год, язык, жанр).
- Нейросетевые и последовательные модели (two-tower, SASRec, BERT4Rec).
- Двухэтапная архитектура: отбор кандидатов + ранжирующий градиентный бустинг.
- Контроль разнообразия и новизны (MMR, штраф за книги той же серии).
